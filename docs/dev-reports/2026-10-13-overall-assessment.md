## 4. 上线可行性分析

### 4.1 作为"本地产品"上线(用户双击即用)

**可行性:中高** — 核心路径已通(冒烟 `/health`/`/preflight` 200),但**未做打包端到端验证**。

**阻塞项**(必须):
1. **E2E 打包烟测**(B5,1.5d·风险)— 不验证就不确定打包产物能否在干净机器跑
2. **supervisor 服务列表统一**(B7,2-3d)— 影响打包后服务启动可靠性(20 处硬编码)
3. **env 前缀统一**(B9,1.5d)— 否则 PRISM_/LAOMA_ 混用致配置失效
4. **工作区提交策略** — 294 文件未提交,需先梳理(背景 vs 本主线)再切分提交

**非阻塞但影响体验**:
- 启动慢 26s(B10,1.5d)
- CI test/lint(B8,1d)— 上线后回归保障

**预估达成时间:1.5-2 周**(B 类 ~8-10d)

**结论**:**接近可上线**,但必须先跑 E2E 打包烟测 + supervisor 统一 + env 统一 + 工作区梳理。**当前不可直接发布**(未验证打包产物)。

### 4.2 作为"SaaS 产品"上线(订阅收费)

**可行性:低(当前)** — 缺所有 SaaS 基建。

**阻塞项**:
1. **§7 决策未拍板**(代理范围/商业模式/支付/云设施/防逆向强度/**离线模式**/Hermes 归属)— 最关键
2. 无用户体系(C12,3-4d)
3. 无订阅/计费(C13,2-3d)
4. 核心资产未下沉(C14 LLM 代理 4-5d + C15 签名代理 3-4d)
5. 无支付(C19,4-5d)
6. 防逆向为零(key 明文 + PyInstaller 可解包)
7. 客户端无双通道(C16,3-4d)

**预估达成时间:4-6 周**(C 类 ~22-30d + 决策周期)

**结论**:**远未上线**,需大量改造 + 决策。且 SaaS 化会修订本地产品的部分设计(key 剥离、Hermes 链路、客户端双通道)。

### 4.3 推荐上线路径

```
阶段 1:本地产品上线(B 类,1.5-2 周)
  → 先让产品能打包、能分发、能跑
  → 拿到真实用户 + 反馈
  → 同时积累测试基础(B8 CI test/lint)

阶段 2:SaaS 化(C 类,4-6 周,需决策)
  → 在本地产品基础上加云端层 + 订阅
  → 本地产品是 SaaS 客户端的基础(浏览器自动化/文件/UI 留本地)
```

**理由**:本地产品化是 SaaS 的地基(客户端仍需本地壳);先上线本地能拿到用户 + 验证产品价值,再决定 SaaS 形态(§7 决策有真实用户数据支撑)。

## 7. 结论

| 上线形态 | 可行性 | 预估 | 当前阻塞 |
|---|---|---|---|
| **本地产品** | 中高 | 1.5-2 周 | E2E 烟测 + supervisor 统一 + env 统一 + 工作区梳理 |
| **SaaS 产品** | 低 | 4-6 周 + 决策 | §7 决策 + 用户体系 + 订阅 + 核心下沉 + 支付 + 防逆向 |

**核心判断**:
- 本地产品**接近上线**但**当前不可直接发布**(未验证打包产物 + 几个收尾未做)
- SaaS 产品**远未上线**,且依赖决策
- **建议先本地后 SaaS**:本地是 SaaS 的基础,先上线能拿用户 + 验证价值 + 积累测试,再决定 SaaS 形态

**最优先动作**:
1. 梳理工作区(294 文件)→ 确定提交策略
2. 做 E2E 打包烟测(B5)→ 验证本地产品能否真发布
3. 同步推进 supervisor 统一(B7)+ env 统一(B9)
4. 拍板 §7 决策 → 启动 SaaS 规划
