## 3. API 集成

### 3.1 capabilities → 模型下拉

`GET /api/v1/ai-design/capabilities`

- 挂载时通过 `authFetch` 拉取
- 下拉展示 `displayName`；值 = `modelKey`
- 选中后 `deriveLimits(model)` 派生 UI 约束（宽高比、maxCount、maxRefImages）

### 3.2 generate → 生成

`POST /api/v1/ai-design/generate`

请求体（`buildGeneratePayload` 构造，对齐 M1 契约）：

```json
{
  "model_key": "dall-e-3",
  "prompt": "a red apple",
  "reference_images": [],
  "aspect_ratio": "1:1",
  "count": 1,
  "agent_id": "agent_abc",            // 仅当选中智能体
  "idempotency_key": "gen_1760000000_abc123"
}
```

- `reference_images` 始终传空数组（当前 M1 provider 全部 `maxReferenceImages=0`；如果传非空后端会 400）
- 素材上传走本地预览（`FileReader` → dataURL → 前端 state），**不真的上传到后端**；后端就绪后可在此接入
- `idempotency_key` 客户端生成 `gen_<ts>_<rand>`；后端目前未做去重，但字段已在契约里
- 响应 `images[]` 渲染为网格；每张提供"编辑"（跳 M5）+ "下载"（浏览器原生 `download` 属性）
- 积分信息展示：`points.total` + `points.status`（`consumed` / `consumed_consume_pending`）

### 3.3 records → 生成记录

`GET /api/v1/ai-design/records?current=1&size=10`

- 挂载 + 生成后自动刷新
- `normalizeRecord` 把后端异构字段（数字/字符串 `created_at`、`id` vs `task_id`）统一成前端展示态
- 每条记录右侧"查看"按钮把该条记录作为 `lastResult` 填入右侧结果卡，便于回看

### 3.4 agents → 智能体下拉（M2）

`GET /api/v1/ai-design/agents` + `GET /api/v1/ai-design/agents/quota`

- **复用 M2 的 `authFetch` 模式**（不重新造轮子）：从 `cloudAuth.getAccessToken()` 拿 JWT → `Authorization: Bearer <token>`
- 下拉：`NO_AGENT_VALUE`（`__none__`）+ `agents[].id`；显示 `name`
- 顶部展示配额 `used/limit`
- 选中后 generate 请求携带 `agent_id`；右侧展示"已选智能体"提示条（含 `style_tokens`）
- 401 → 顶部黄色 banner 提示登录（对齐 M2 `agent-studio-panel.tsx` 的行为）

## 5. M5 编辑器跳转

### 5.1 页面侧

图片网格中每张图的"编辑"按钮：

```tsx
window.open(buildEditorUrl(url), "_blank", "noopener,noreferrer")
```

`buildEditorUrl("https://x/1.png")` → `/tools/image-editor?url=https%3A%2F%2Fx.com%2F1.png`

### 5.2 编辑器侧

修改 `prism_frontend/src/app/tools/image-editor/page.tsx` 为两层结构：

- **外层**（server component）：包 `<Suspense>`，兼容 `export const metadata` 语义
- **内层**（client component）：`useSearchParams` 读 `?url=`，只允许 `http(s)` 协议，传给 `<ImageEditor initialUrl={...}>`

修改 `prism_frontend/src/components/image-editor/image-editor.tsx`：

- `ImageEditorProps` 新增 `initialUrl?: string`
- 挂载时若有 `initialUrl`：`fetch(url)` → `blob` → `FileReader.readAsDataURL` → `setSrcDataURL` + `setStage("crop")`
- 加载失败时 toast 提示并保持在"上传"阶段（不阻断用户使用本地上传）
- `cleanupFabric` / `resetEditor` 从文件末尾 hoist 到 `onDrop` 之前，供 preload effect 复用（避免"在声明前使用"）

## 8. 关键实现取舍

1. **抽纯逻辑层 (`lib/image-studio.ts`)**：与 M2 `agent-studio.ts` / M4 `wizard-core.ts` 一致，所有类型定义、常量、派生函数、请求体构造、URL 拼接都在纯函数里；UI 只做渲染 + 状态。这是本项目既有的"UI 薄、逻辑厚、可脱离 React 单测"约定。
2. **不做 DOM 交互测试**：项目未装 `@testing-library/react`；DOM 层通过抽纯函数 + 静态类型检查覆盖。M4 报告 §5.2 有同样取舍，此处延续。
3. **authFetch 复用不重复造轮子**：与 M2 `agent-studio-panel.tsx` 完全同构的 `authFetch`（`cloudAuth.getAccessToken()` + `Authorization: Bearer`）；没有把这段提到公共 lib，是因为 M2 页面也是就地内联，保持一致。若后续要复用，可考虑抽到 `lib/auth-fetch.ts`。
4. **M5 URL 预加载的最小侵入**：只给 `ImageEditor` 加了个可选 `initialUrl` prop；不改变组件既有 API（无 `initialUrl` 时行为完全不变）；page.tsx 从纯 server 拆成 server + client 两层以支持 `useSearchParams`。
5. **素材图只做本地预览**：M1 后端所有 provider 的 `maxReferenceImages=0`，即使前端真的上传到后端也会被 `/generate` 400。保留上传 UI 是为后续扩能力（gpt-image-1 edit / ComfyUI 参考图）预留骨架位。
6. **`reference_images` 始终传空数组**：即便用户上传了本地预览素材，`buildGeneratePayload` 也传 `[]`；避免用户误以为上传了就能生效。UI 上在 `currentModel.maxReferenceImages===0` 时明确提示"当前模型不支持参考图"。
