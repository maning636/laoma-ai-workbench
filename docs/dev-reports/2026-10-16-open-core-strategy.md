### 2.2 核心判断逻辑

**开源什么** → 凡是"用户拿到后能立刻体验价值、且不含核心 IP"的:
- 矩阵发布(基础版:3 账号/3 平台)
- 账号管理(基础版:3 账号)
- 素材管理(基础版:无 AI 润色)
- 浏览器自动化(patchright 直连,无 Persona 指纹)
- 排期/任务管理
- 开发者工具中心

**付费什么** → 凡是"消耗云端资源/含核心 IP/竞品也收费"的:
- AI 内容生成(prompt 模板 + LLM 代理 → 云端持有 key)
- Hermes Agent(任务型 AI → 云端)
- 数据回收(TikHub API 有成本)
- Persona 指纹增强(反检测层)
- 代理管理(IP 隔离/防关联)
- 高级发布(无限账号/平台/定时)

## 三、Open Core 分层方案

### 3.1 Community Edition(开源,GitHub)

```
免费、可自部署、但有限制:
├── 矩阵发布:3 账号 / 3 平台 / 基础定时
├── 账号管理:扫码登录 / Cookie 导入(3 账号上限)
├── 素材管理:上传 / 手动标题标签(无 AI 润色)
├── 浏览器:patchright 直连(无 Persona 指纹)
├── 排期日历 / 任务管理
├── 开发者工具中心
├── AI 对话:自配 key(离线模式,走本地 .env 的 key)
│   └── 用户自己出 LLM key,免费体验基础 AI
└── 注册/登录/订阅 UI:全部内置(引导付费)
```

**关键设计**:用户下载后**能跑起来**(体验价值),但:
- AI 用的是**自己配的 key**(基础 prompt 档,不够聪明)
- 只有 3 账号 3 平台(不够用)
- 没有指纹防护(容易关联)
- 没有数据回收(看不到效果)

→ **用着用着就发现需要升级**(自然转化)。

### 3.2 Pro Edition(订阅,云端服务)

```
月付/年付,云端持有 key + prompt:
├── 无限账号 / 8 平台 / 高级定时
├── AI 内容生成:云端 prompt 模板(高价值,防逆向)
├── Hermes Agent:云端代理(不用自配 key)
├── 数据回收:TikTok/YouTube/B 站/抖音数据
├── Persona 指纹增强:反检测/Profile 持久化
├── 代理管理:IP 池/sticky/地区映射
├── 视频流水线:高级模板
└── 流式 AI 对话:SSE 逐字输出
```

### 3.3 转化路径(GitHub → 注册 → 付费)

```
1. GitHub 下载 → 安装 → 启动
2. 首次打开 → 注册页(已在客户端内置)
3. 注册成功 → 免费额度(20 次/月 AI 调用)
4. 用 3 账号 3 平台发布 → 觉得好用
5. 想加更多账号/平台 → "升级 Pro" 按钮
6. 订阅 → 云端代理生效(订阅态自动切换)
7. AI 走云端(prompt 不可见) → 防逆向
```

## 五、开源风险与防护

### 5.1 风险

| 风险 | 严重度 | 缓解 |
|---|---|---|
| 竞争对手 fork 后去掉付费限制 | 🔴 高 | 核心价值在**云端服务**(prompt + key + 数据),不在客户端代码;fork 后没有云端 = AI 不聪明 + 没数据 |
| 用户自部署不付费 | 🟡 中 | 自部署 = 自配 key(基础 prompt 档);体验明显不如云端(这就是转化点) |
| 安全漏洞暴露 | 🟡 中 | 代码开源 = 安全研究者能审;好处大于坏处(社区贡献修复) |
| 支付绕过 | 🟡 中 | 支付代码开源,但**云端服务不开源**(订阅校验在云端 license/verify) |

### 5.2 核心防护:云端持有的资产

**开源的只是"客户端外壳",真正值钱的在云端**:

| 资产 | 位置 | 开源? |
|---|---|---|
| prompt 模板(9 个高价值) | 云端 `prompts` 表 | ❌ 不开源 |
| LLM key | 云端 env | ❌ |
| license 校验逻辑 | 云端 `/cloud/license/verify` | ❌ |
| 数据回收(TikHub) | 云端代理 | ❌ |
| Hermes Agent 内核 | 云端 | ❌ |
| **客户端代码**(发布/账号/素材/UI) | GitHub | ✅ 开源 |

**结论**:即使有人 fork 去掉付费限制,他**拿不到云端 prompt + key + 数据服务** → AI 不够聪明、没有数据回收 → 价值大幅缩水。这就是 Open Core 的核心逻辑:**开源壳,付费核**。

## 七、实施路线

### Phase 1:GitHub 开源准备(2-3 人日)

1. **拆分 Community / Pro 代码边界**:
   - Community:移除云端 prompt 引用 → 降级为 basic prompt
   - Pro:保留云端代理 + 订阅校验
2. **License 文件**:AGPL-3.0(强制 fork 后也开源,防止闭源竞品)
3. **README 改写**:突出"下载即用 + 注册升级"路径
4. **`.env.example`** 精简:只留 Community 必需的(自配 key / 基础配置)
5. **打包 Community 版**:不含云端 prompt 的安装包

### Phase 2:注册转化(3-5 人日)

1. **客户端内置注册页**:已有(`login/page.tsx`)
2. **免费额度自动分配**:已有(C13 billing)
3. **"升级 Pro" 按钮**:在 `cloud-subscription-card.tsx` 加转化入口
4. **支付流程**:已有(C19 微信/支付宝)
5. **子域名 + HTTPS**:等用户提供 DNS + 证书

### Phase 3:社区运营(持续)

1. **GitHub Issues** 模板(bug report / feature request)
2. **文档站**(docs/ → GitHub Pages)
3. **Discussions** 社区
4. **Contributing.md**

## 八、总结一句话

> **开源"能用但不够爽"的壳(发布/账号/素材/基础 AI),付费"很爽但不可抄"的核(云端 prompt/Hermes/数据/指纹)。**
> 
> 用户从 GitHub 下载 → 3 账号够玩 → 想要更多 → 注册 → 免费额度(20 次 AI) → 用完 → 升级 Pro(¥99/月) → 云端代理生效 → AI 变聪明 + 数据回流 + 指纹防护。
> 
> fork 竞品?他拿不到云端 prompt + key + 数据 → AI 不够聪明 → 用户还是会回来付费。
